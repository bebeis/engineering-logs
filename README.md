# Engineering Logs

프로젝트를 진행하며 해결한 문제와 개발 블로그에서 다룬 코드를 한곳에 모아 둡니다.
각 사례는 독립적으로 살펴볼 수 있도록 문제 해결에 필요한 최소 범위의 코드만 담습니다.

## 프로젝트

| 프로젝트 | 문제 해결 사례 |
| --- | --- |
| [Cluverse](./cluverse/) | [게시글 목록 조회 설계 및 개선](./cluverse/post-list-query-optimization/) |

## 디렉터리 구조

```text
engineering-logs/
├── README.md                         # 전체 프로젝트와 사례 색인
└── <project>/
    ├── README.md                     # 프로젝트 설명과 사례 색인
    └── <problem-solving-case>/
        ├── README.md                 # 문제, 해결 방법, 블로그 글 링크
        └── code/                     # 사례를 이해하는 데 필요한 코드
            └── README.md             # 코드 구성과 실행 방법
```

## 사례 추가 규칙

1. 루트에 프로젝트 디렉터리를 `kebab-case`로 만듭니다.
2. 프로젝트 README에 프로젝트 설명과 문제 해결 사례 링크를 추가합니다.
3. 프로젝트 아래에 사례 디렉터리를 `kebab-case`로 만듭니다.
4. 사례 README에 문제, 접근 방법, 결과, 블로그 글 링크를 기록합니다.
5. `code/`에는 문제 해결과 직접 관련된 코드만 두고, 원본 프로젝트의 패키지 구조를 가능한 한 유지합니다.
6. 루트 README의 프로젝트 표에도 새 사례를 연결합니다.

사례 README는 아래 항목을 기본 골격으로 사용합니다.

```markdown
# 사례 이름

문제와 해결 결과를 한두 문장으로 요약합니다.

## 관련 글

- [블로그 글 제목](https://example.com)

## 문제

- 어떤 현상 또는 제약이 있었는지
- 기존 방식이 왜 충분하지 않았는지

## 해결

- 적용한 핵심 변경
- 선택의 근거와 중요한 트레이드오프

## 결과

- 측정값 또는 검증 방법

## 코드

- [`code/`](./code/): 주요 코드와 실행 방법
```
