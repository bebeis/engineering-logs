# Engineering Logs

프로젝트를 진행하며 해결한 문제와 개발 블로그에서 다룬 코드를 한곳에 모아 둡니다.
각 사례는 독립적으로 살펴볼 수 있도록 문제 해결에 필요한 최소 범위의 코드만 담습니다.

이 저장소의 코드는 전체 애플리케이션 복사본이 아니라 문제 해결에 사용한 핵심 코드 발췌입니다.
빌드를 위한 공통 설정과 주변 도메인은 의도적으로 생략할 수 있으며, 각 사례 README에서 생략 범위를 밝힙니다.

## 디렉터리 구조

```text
engineering-logs/
├── README.md                         # 전체 프로젝트와 사례 색인
└── <project>/
    ├── README.md                     # 프로젝트 설명과 사례 색인
    └── <problem-solving-case>/
        ├── README.md                 # 문제, 해결 방법, 블로그 글 링크
        ├── v1-<baseline>/             # 최초 구현 또는 문제 재현 코드
        └── v2-<improvement>/          # 다음 개선 단계의 코드
```

## 사례 추가 규칙

1. 루트에 프로젝트 디렉터리를 `kebab-case`로 만듭니다.
2. 프로젝트 README에 프로젝트 설명과 문제 해결 사례 링크를 추가합니다.
3. 프로젝트 아래에 사례 디렉터리를 `kebab-case`로 만듭니다.
4. 사례 README에 문제, 접근 방법, 결과, 블로그 글 링크를 기록합니다.
5. 사례 디렉터리 바로 아래에 `v1-<요약>`, `v2-<요약>` 형식으로 구현 단계를 나눕니다.
6. 버전 번호는 글에서 개선한 순서를 따르고, 이름에는 해당 단계의 핵심 변경을 `kebab-case`로 적습니다.
7. 각 버전 디렉터리에는 문제 해결과 직접 관련된 코드만 두고, 원본 프로젝트의 패키지 구조를 가능한 한 유지합니다.
8. 각 버전 README에는 이전 버전과 달라진 점, 읽는 순서, 검증 방법을 기록합니다.
9. 루트 README의 프로젝트 표에도 새 사례를 연결합니다.

사례 README는 아래 항목을 기본 골격으로 사용합니다.

```markdown
# 사례 이름

문제와 해결 결과를 한두 문장으로 요약합니다.

## 관련 글

- [블로그 글 제목](https://example.com)

## 문제

- 어떤 현상 또는 제약이 있었는지
- 기존 방식이 왜 충분하지 않았는지

## 해결

- 적용한 핵심 변경
- 선택의 근거와 중요한 트레이드오프

## 결과

- 측정값 또는 검증 방법

## 버전별 코드

- [`v1-baseline/`](./v1-baseline/): 최초 구현 또는 문제 재현
- [`v2-improvement/`](./v2-improvement/): 다음 개선 단계
```
